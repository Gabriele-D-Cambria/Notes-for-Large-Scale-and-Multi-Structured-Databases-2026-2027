## 📋 Exam

The exam consists in a group project (50%) and a written test (50%) with three
open questions (~40 minutes) on theoretical parts.

### Project

The groups for the project must be decided by the end of November.

The project is an _**Application interacting with NoSQL Databases**_.

The suggested workflow is:

1. Start with an idea and a draft of application requirements, use case
   diagrams and data entities (quick discussion in the classroom during the
   course or during meeting slots, **to be approved by the teacher**).
1. Refine requirements and use cases.
1. Define data entities and relationships by means of UML analysis class diagrams.
1. Provide the design of the Data Base (at least two of the main non
   relational models must be considered when defining the requirements. **Document
   DB model is mandatory**).
1. Define the main queries on the Data Base(s).
1. Implement and deploy the application, hopefully on Virtual Lab handed by the
   professor.
1. Test the application (by running the implemented RESTful APIs, details will
   be provided ).
1. Write a complete documentation resuming the above items and including an APIs
   documentation.

The use of AI is not prohibited, but be careful on how it's used.

The project must be developed in **groups of 3 students** (problems in the
group are to be solved individually).

**No reviews** are allowed, students will receive a number of example of past projects.

The project **must be discussed before the written test**, in a date fixed by
the professor. The documentation must be handed in advance of the discussion.
The mark of the project is permanent for eternity.

The evaluation will be:

- 25% for the idea, requirements, entity-relationship model and UML diagrams
- 40% for DB design and query definition
- 25% for the implementation of APIs
- 10% clarity of the overall documentation

The _individual assessment_ will depend on:

- Overall evaluation of the project
- Answers given by the specific student during the **project discussions**

## 🎯 Course Structure

In this course we will talk about:

- Big Data
- Fundamentals and properties of NOSQL databases: ACID vs BASE properties,
- Architectures of NoSQL databases
- Modern infrastructures for NoSQL Databases (REDIS, MongoDB, Neo4J)

The timeline will be something like this:

1. September to end of October/beginning of November:
   1. Introduction to main NoSQL architectures and strategies.
   2. Recaps of Software Engineering and Java (with exercises)
   3. Example of Application based on NoSQL DB Architectures
   4. Introduction to the Project and Student Group Definition (1° round)
2. November:
   1. Introduction to main features of NoSQL infrastructures (REDIS, MongoDB,
      Neo4j)
   2. Student Group Definition (2° round)
3. End of November to end of academic year:
   1. Student Group Definition (3° round)
   2. Project idea discussion
   3. Project Development
